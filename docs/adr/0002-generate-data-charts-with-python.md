# Generate data charts with Python

Every Data Chart is rendered during the task from structured data by delivered Python source and supplied to full-slide image generation as required visual context; this workflow does not accept image-only charts without underlying data. Its Chart Source Package also contains the exact data snapshot used for that run, rather than depending on a live API, database, or mutable report. Chart generation uses the skill-managed Matplotlib, pandas, NumPy, and Seaborn toolchain; chart scripts do not install their own dependencies, and additional chart libraries require explicit user approval. Each rendered chart has a transparent background, contains only the axes, scales, legends, units, and labels needed to understand its data, and follows the confirmed deck palette without adding slide titles, narrative copy, cards, borders, shadows, or decorative containers.

The image backend generates the complete slide layout without a reserved chart placeholder or deterministic local compositing. Because a generative backend cannot guarantee pixel-exact chart preservation, the Slide Image Set is authoritative only for layout and style: numerical discrepancies inside a generated full-slide image do not supersede its Chart Source Package. The editable-PowerPoint workflow must use the data snapshot as numerical truth, the Python source as the reproducible visual specification, and the rendered chart as the appearance reference instead of inferring chart values from the full-slide image. The final editable PPTX is the artifact that must combine the intended layout with accurate native charts. A deck-level `chart_manifest.json` maps every chart package to its slide and semantic role so multiple charts per slide and later page reordering remain unambiguous; it deliberately does not record chart coordinates or dimensions, because chart detection and placement belong to the editable-PowerPoint workflow.
