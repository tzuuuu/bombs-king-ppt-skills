# 标准工作流

## 总览

Codex PPT 的工作流强调阶段确认。它不会一上来直接生成整套 PPT，而是先确认大纲、风格、图片后端和样张，降低返工成本。

## 阶段 1：阅读输入材料

agent 会先理解：

- 主题和核心观点
- 目标受众
- 演示目标
- 页数要求
- 必须包含或排除的内容
- 是否有必需图片素材

agent 会先向你展示来源简报，并提供资产清单；每项素材会记录来源或路径、预定用途与当前可用状态。核心字段必须有明确值或经你确认的假设，未解决问题会保持此阶段未完成。
如果你指定了 `.ppt` 或 `.pptx` 母片模板，agent 会在这个阶段先将它复制到 `template/template.ppt` 或 `template/template.pptx`，导出 `template/template.pdf`，并 render 成 `template/template-1.png` 等逐页底稿；同时记录每页预定使用的母片页面。

## 阶段 2：确认大纲

agent 会生成 `outline.md`，通常包括：

- Slide 编号
- 每页标题
- 3-5 个要点
- 页面角色，如封面、目录、概念解释、流程、对比、数据证据、总结等
- 可选视觉想法
- 必需图片素材及其用途

大纲确认前，不应生成正式 slide 图片、图表来源包或 `speech.md`。

## 阶段 3：确认视觉风格

agent 会给出 2-3 个风格方向并推荐一个。候选风格来自 12 种内置风格（清爽专业风、科研答辩风、手绘技术解释风、麦肯锡风格、党政红风格、教学课件风等）和你的个人风格库，也可以基于你提供的截图、PDF 或 PPT 复刻风格。完整风格预览参见[风格与个人风格库](styles.md)。

选择风格后，整套 PPT 应保持统一视觉语言，但每页版式可以根据内容变化。

## 阶段 4：确认图片生成后端

优先使用 Codex 内置图片生成工具。只有在内置工具不可用、用户明确要求 API/CLI fallback，或当前能力无法满足时，才切换到 `scripts/image_gen.py`。

图片后端确认后，整套 PPT 应保持一致，不应中途切换。

## 阶段 5：生成并确认样张

先生成 1 页样张，检查：

- 文字是否清晰
- 风格是否符合预期
- 页面密度是否合适
- 色彩和排版是否稳定
- 是否适合批量扩展到整套 PPT

样张通过后，再批量生成整套。每页 prompt 会尽可能先规划 approved sample、该页图表素材与母片底稿 `template/template-<N>.png`。子智能体的中间候选图统一写入项目工作区的 `generated_images/`，由 parent agent 将选中的候选图复制到 `origin_image/slide_XX.png`。生成图片不包含可见页码，但文件名仍使用 `slide_XX.png`。

## 阶段 6：批量生成

样张确认后，agent 会为每个待生成页面分配一个子智能体，并尽量填满可用并发槽位；当前 skill 的页面 worker 默认容量为 30。某个 worker 返回后，agent 会立即记录结果并把下一个待生成页面补入空出的槽位，不让可用槽位或页面任务闲置。所有页面沿用样张确认的同一风格和同一生图后端。

## 阶段 7：质量检查与修复

交接前，agent 会逐页检查文字清晰度、与大纲的一致性、内容截断、风格统一性、多余页码、元素重叠与必需数据图表。严重问题页面会用更严格的提示词重新生成，局部小问题优先用图片编辑能力修复。

## 阶段 8：演讲稿与项目工作区交接

生成 `speech.md` 并保留给后续重建，然后运行项目工作区交接验证。PPTGen 不组装中间 PPTX。存在数据图表时，每张规划图表都必须有 Python 生成器、实际 CSV/JSON 快照、透明 PNG 与 manifest 记录。

## 阶段 9（可选）：保存风格

如果这套 PPT 用的是自定义或调整过的风格，agent 会在最终报告里提示你可以把风格保存到个人风格库，以后直接按名字复用。参见[风格与个人风格库](styles.md)。
